# Rising Roots Home Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the Home page to follow the Rising Roots reference section by section, from builder blocks Tynnell can edit, with every section that needs her words hidden until she fills them in.

**Architecture:** One small shared gate (`GateEmpty` plus pure "is this empty" rules) wraps each hideable block, controlled by a per-block "Hide until filled in" switch that is off for every existing block. Two new blocks (Statement, Path Choice) and additive fields on Stats Row, Album Grid, Live Testimonials (a Slider layout) and Email Signup (freebie readiness) fill the gaps. The Home page itself is data: a pure `buildHome()` function produces the Puck document, used both for a blank `home` starter template and for a script that writes the new Home into page 43's `draft_content`, so production keeps rendering the old `content` until Alex approves publishing.

**Tech Stack:** Next.js 16 App Router, React, Puck 0.20.2 (`app/builder/puck.config.tsx`), Payload v3, vitest + Testing Library (jsdom), `tsx` for the script.

**Spec:** `docs/superpowers/specs/2026-11-16-home-page-design.md` (read it first; this plan only records decisions the spec leaves open).

## Global Constraints

- No em dashes anywhere (code, comments, strings, docs, commit messages).
- No Tailwind. Inside `puck.config.tsx` blocks use inline styles and the existing helpers (`Section`, `headingStyle`, `eyebrowStyle`, `btnStyle`, `C`, `imageField`, `styleFields`, `styleDefaults`, `responsiveFields`, `responsiveDefaults`, `visClass`). Fonts only through variables (`HEADING_FONT`, `BODY_FONT`, `var(--font-script-role, var(--font-heading))`); never write a font family name (the PR #155 bug).
- Existing blocks change only by ADDING optional fields; saved pages must render exactly as before (the hide switch defaults to off).
- Puck's preview iframe stays disabled. Render props carry `puck.isEditing` (Puck 0.20); tests pass `puck: {}`, so always read it as `puck?.isEditing`.
- Never invent a stat, quote, name or bio. Words carried over are the ones already on the live Home page (page 43).
- No schema change expected. If one is needed: block in `scripts/migrate-db.mjs`, regex test in `scripts/migrate-db.test.ts`, then `npm run generate:types`.
- Tests first, watch each fail. Keep tests lean: behaviour tests; no CSS-text tests except as a contract for a past bug (Alex's feedback, 2026-11-16).
- Commit messages carry NO `Co-Authored-By` (project rule). PR bodies end with the Claude Code line.
- PowerShell only. Branch: `feature/0000262-rising-roots-home` (already cut; spec committed). Next branch number afterwards: 0000263.
- Never use the in-app Browser pane. Visual checks go through Claude in Chrome on the Vercel preview.
- Production data is written only in Task 10's script (draft only) and only after the PR is merged. Publishing the draft (the swap into live `content`) waits for Alex's explicit yes.

## Review Focus

1. A saved page whose block is empty and has no hide switch (every existing page) must still render (Task 1 gate test, repeated per block in Task 4 to 8 via `hideSwitch.test.tsx`).
2. In the editor an empty hidden section must show a visible outline, never nothing, or Tynnell cannot find it (Task 1, Task 2, Task 3).
3. A hidden section leaves no padding or stray heading behind on the public page, including Album Grid's own "Albums" heading (Task 6).
4. The freebie readiness check fails closed: endpoint error, network failure or missing link all hide the freebie sign-up, and the endpoint returns only a boolean (Task 8).
5. Testimonials slider with 0, 1, 2 and many items, and `resolveData` failure, never errors or shows a lone control (Task 7).
6. `homeWordsFromCurrent` on a page missing sections or with elements reordered returns blanks, never the string "undefined" and never throws (Task 9).
7. The new Home's first block is a Hero with a photo, so the nav stays transparent over it (Task 9, using `markNavHero`).
